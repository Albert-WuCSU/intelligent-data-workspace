# 产品任务审查 / self_review

## 为什么上一片仍不够
A2只把最终短句和澄清表单置于结果卡上方，过程解释未按时间进入聊天，正文仍像结果卡附属说明。PRD里的“连续对话”缺少可观察行为，不能用技术测试通过反驳用户体验反馈。

## 本片取舍
保留业务对话和真实顶部pipeline，用只含公开事实的AgentDialogueEntry在主聊天保留过程说明/真实工具标签/澄清问答；结论正文先行、后端数值与表内嵌，SQL回执折叠。信息层级仿常规Agent，不仿截图中的企业数据/工具权限。技能/模型最终prompt改报告要求，避免“只看结果卡”。

当前不把完整模型中间文本/原始thinking实时转发：公开治理事实足以说明正在做什么，文本来源明确；模型最终公开解释正常渲染。模型中间流式公开消息的脱敏/receipt/provenance需后续受控实现，不能声称此片已经提供。也不扩结果行外发：数值正文由后端已发布数据生成，模型只解释范围/限制。

## 可观察验收
- 已发生元数据工具在对话出现说明和紧凑标签，而不仅右侧日志。
- 澄清和用户回答按事件顺序出现在同一任务，回答后才出现继续规划说明；没有模拟Bash或思维链。
- 最终报告含范围、来源、质量/限制、下一步和后端权威数值；SDK结果容器不再有result-card外壳；细节可折叠。
- 失败/轮询读取失败不丢收到的回答/结果；未配置模型不冒充正在执行；主题/历史/手机保留。
