- 默认数据源：已有 1 个启用来源（Excel 订单表，`source_id=c0ea94d5-d9e0-406d-8037-6b018f7ff871`，表 `t0`，字段含 `编号`、`created_at`、`发货日期`、`金额`）。
- 已发布语义：**0 个**。这是当前唯一的数据侧阻塞；`DEMO_SEMANTIC_DRAFT.json` 是给该来源准备的可导入草稿，仍需用户校验/批准/发布。
- 估算账本：已用 15/60 单元（其中 5 completed、10 failed_or_unknown），剩余 45 单元；本次模型测试约 1 单元（0.25 USD），SDK 任务预留 8 单元（2 USD 估算），门禁足够。
- 真实模型：尚未配置；Key 只能由用户在本机网页安全输入。

## 步骤 1：配置并启用模型

1. 打开 `http://127.0.0.1:5173`，左侧进入“设置 → 模型服务”。
2. 选择公司 AI Plan 预设；地址/协议/认证保持固定，模型预填 `deepseek-v4.1-flash`。
3. 在专用 Key 输入框输入你的产品 Key（不要发到聊天；页面提交后清空，仅后端内存保存）。
4. 勾选同意固定非敏感测试与估算，保存连接。
5. 点击最小模型测试（约 0.25 USD 估算预留，不是账单）；成功后在目录中启用该模型。
6. 回到工作台，确认模型选择器显示该模型为“可用”。

若测试失败：保留回执/错误码，不要自动重试或换模型；把页面上的安全错误码/诊断告诉维护者。

## 步骤 2：导入并发布演示语义

1. 打开“知识库”。
2. 选择已启用的 Excel 订单表来源，表 `t0`。
3. 展开“导入结构化定义（可选）”，上传 `project-control/modules/M04/evidence/20261104T032252Z/DEMO_SEMANTIC_DRAFT.json`。
4. 导入后点击“校验实际字段与口径”；确认指标为 `sum(金额)`、粒度 `编号`、单位显示“未声明单位”。
5. 勾选人工批准，点击“发布语义版本”。
6. 回到工作台，确认语义版本选择器出现“订单总金额 · v1”。

说明：`未声明单位` 是刻意不推断币种；如果你确认金额单位，可在发布前修改。该口径是本机演示定义，不是企业认证指标。

## 步骤 3：真实 Web 问数

1. 工作台选择刚发布的语义版本、`deepseek-v4.1-flash` 模型，并勾选该 Excel 来源。
2. 勾选“同意问数模型外发和估算”。
3. 输入：`请计算总金额，全部数据`，点击发送。
4. 任务卡应显示 `Claude Agent SDK · 受治理问数`，先进入“等待确认执行”；核对指标、全表、粒度、单位后，勾选确认并点击“确认执行查询”。
5. 预期：受治理 MCP 对完整输入聚合，自动 QA，结果卡显示总金额；SQL/Schema 折叠；结果行不返回模型。

若任务失败：记录任务卡上的 `error_code`、事件和任务编号；不要重复提交未知结果。SDK 运行目录在任务结束后清理，失败根因可能需要根据错误码重新运行。

## 边界

- 本测试使用本机 Excel 来源和真实 DeepSeek 网关；DeepSeek 仍是非 Claude/unsupported 路径，不关闭 `sdk-real-gateway`（Claude）门禁。
- 不自动发现网关模型、不新增端点/供应商、不读取宿主 Key/settings/hooks、不自动收费或扩大外发。
- 真实测试完成后把结果/截图/回执交给维护者保存证据；MVP 整体（M05–M08）仍未完成。
