## 1. 祖训（产品设计原则）

### 1.1 先分类，再按优先级取数

1. 判断请求类别：取数（是多少）、分析（为什么变/变在哪）、归因、其他（概念/闲聊）。
2. 取数类按四层递进，能走前面就不往后走：
   - **L1 指标引擎**：标准指标 + 常规维度/时间优先；快、口径稳。
   - **L2 主题 SQL Skill**：L1 不适用或失败，匹配业务主题 Skill（表名 + 口径模板 + 字段合同）。
   - **L3 查表选型 + 受控 SQL**：前两层无现成，按权限清单搜表/字段/分区，模型提出受控 SQL，Harness 校验后执行。
   - **L4 知识咨询/RAG 兜底**：表或口径含义不清，先查数据字典/业务知识文档，确认后再写 SQL。
3. 分析/归因与取数不同：优先归因引擎；多轮下钻；最终出结构化结论/报告；不把相关性写成因果。
4. 权限拒绝就停下说明申请/换路径，不换账号、不绕权限、不猜表。

### 1.2 SQL 之前必须确认

- 口径（离店/预订、含不含取消、指标定义、时间口径）；
- 表真实存在、字段真实存在、分区范围；
- 必需维度/粒度/关联键/基数；
- 拿不准必须反问，不猜；关键歧义一次问清，不反复问已知槽位。

### 1.3 执行后必须质检与标来源

- 每次取数自动 QA；FAIL/UNKNOWN 不得包装成功；WARN/空/部分结果解释限制。
- 结果标来源可信类型：指标引擎（标准口径）、受控 SQL（SQL 自查，黄标）、业务文档/推理（红标/参考）——颜色不是因果或企业认证。
- 结果行不回传模型；结果卡/回执是数值权威；模型负责解释、假设、限制和下一步。
- 报告要包含：结论、口径、数据来源、质量/限制、可操作下一步。

### 1.4 交互原则

- **连续对话优先**：用户问题、Agent 中间说明/澄清/工具进度、最终回答都在同一会话；卡片/表格/回执作为证据嵌入，不替代对话。
- 工具步骤只展示实际发生的事件（搜表、读字段、SQL、QA、回执），不展示原始思维链，不用动画模拟。
- 右侧摘要显示实际检索到的数据源、表/字段/分区、任务进度、质量与限制。
- 不把工程验证器当业务首页；SQL/Schema/工具日志默认折叠。

### 1.5 安全与数据边界（不可妥协）

- 只通过治理 Harness 暴露受控工具；**不向模型开放宿主 Bash/Write/任意 Read/WebFetch/子 Agent/宿主 Key/settings/hooks**。
- 公司 Hive、dashboard、公司 MCP、截图中的业务数据/SQL 不在当前产品授权范围；参考图只作交互参考，不复制数据、SQL、水印对象。
- 企业数仓接入必须是新的连接器/权限/安全评审；不能借用当前助手的 MCP 或凭证。
- 所有 SQL 只读、AST/字段/方言/分区/扫描预算/权限校验；确认、幂等、回执、预算门禁保留。

## 2. 目标架构

### 2.1 会话与 Agent 循环

- 会话（conversation）承载多个 turn；每个 turn 有用户消息、Agent 消息、工具事件、澄清问答、结果/报告。
- Agent 循环在一次任务内持续：分类 → L1/L2/L3/L4 → 澄清（可恢复）→ 计划 → 用户确认 → 执行 → QA → 发布 → 解释/报告。
- 澄清必须可在同一任务内恢复：用户回答后继续原计划，不重新开一个卡片任务。
- 任务状态、工具事件、结果卡、回执在右侧摘要可查；聊天区是主叙述。
- 生产持久化/多租户仍属 M05；当前内存任务只作本机演示。

### 2.2 四层工具

| 层 | 工具/能力 | 现状 | 目标 |
|---|---|---|---|
| L1 | 已发布指标引擎、指标/维度/时间/筛选 | 已有（A1） | 保留并作为首选 |
| L2 | 业务主题 SQL Skill/模板、表/口径合同 | 无 | 新增产品 Skills（业绩/流量/订单等），版本化 |
| L3 | 授权表/字段/分区检索、受控 SQL 生成/校验/执行 | 只有单表指标聚合 | 新增 metadata 工具 + 只读 SQL 校验/执行 |
| L4 | 业务知识文档、RAG 检索/引用 | 无（M03 仅结构化语义） | 新增文档导入/切片/版本/检索/引用 |

### 2.3 UI

- 聊天区：用户消息 + Agent 自然语言回答/澄清/报告；不是只有任务卡。
- 任务卡：计划、确认、结果表、回执、SQL 折叠；作为证据。
- 右侧摘要：实际数据源、表/字段/分区、工具步骤、质量、限制、预算/回执。
- 明确状态：未接入/需要澄清/等待确认/执行中/QA/失败/部分结果，不模拟。
- 空态/失败/权限拒绝/取消/恢复都要有可行动下一步。
