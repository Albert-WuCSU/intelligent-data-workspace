# M02-C03 用户可配置连接器返工方案

2026-10-27 当前状态：M02-C03 DO，D-M02-CONNECTOR-UX-005已批准；以下原PLAN方案保留。已实现范围以末尾检查点及progress证据为准，不把完整计划称为已实现。

## 问题与事实

C02 已实现真实网页→API→stdio MCP→固定DuckDB预览，并非静态模拟。但 ConnectorManager 只有 owned-synthetic，服务从固定路径启动，字段/五表/来源/币种硬编码；没有新增、配置、导入、保存、重新连接流程。技术测试证明固定链路可用，不能证明用户能接自己的数据库。针对用户本次核心接入任务，产品验收不通过。

保留C02真实执行、安全/幂等等可复用代码和测试、完整数据/DDL/Parquet，记录历史局限；不重建M01，不继续将这页称为可配置连接器，也不提前关闭M02。

## 用户任务与默认路径

接入人员在本机Web工作台提供自己有权使用的数据源，确认允许读取范围并建立可复用连接；业务用户选择已接入数据源，不配置MCP、密码或Schema。主任务是“把我的数据接进来”，不是先写SQL验证。

连接器首页：显著的【新增数据源】、【配置 MCP】、【导入连接配置】入口，已保存的数据源列表。现有合成仓标【内置示例】，用户选择使用，不自动当作用户已配置来源。

统一流程：选择类型→输入连接信息/选择文件→检查配置→测试连接→确认可用表/字段及只读范围→保存并启用。测试默认只做握手、鉴权和目录，不执行数据SQL；预览是保存后的次级操作，需独立确认。

成功标准：从空配置开始，无需开发者修改源码、服务器环境变量或填写JSON，用户可通过表单或导入建成一个真实连接；刷新后看到服务器保存的配置（不含明文秘密），可编辑/重测/禁用；失败保留输入并给出对应下一步。开发者预置连接不计入该验收。

## 推荐首轮支持范围（待批准）

1. **数据库**：PostgreSQL，主机、端口、数据库、用户名、SSL模式与密码/安全秘密引用。DuckDB走本地来源；MySQL/Spark/Hive不假装通用URL可接，未实现不出现可用入口，后续按需扩展。
2. **本地数据**：DuckDB文件/受控本机路径，CSV/Parquet浏览器文件选择上传。普通用户上传到后端隔离导入区，再由治理MCP只读查询；已有本机文件可用“后端可访问的路径”明确高级输入，不冒充浏览器能读取任意本机路径。
3. **已有MCP**：HTTP MCP服务地址与选定认证方式，或导入非秘密JSON配置。支持协议先验证官方SDK的Streamable HTTP；旧SSE按实测提供明确支持/不支持。配置文件不是可执行脚本，不执行任意command/args、下载插件、shell或导入代码。

不能承诺“任意链接都能连接”：地址须由后端可访问、有凭证/权限且协议受支持。数据库连接不是MCP地址；工具协议相同也不代表工具名/参数/SQL方言相同。外部MCP只能经已审定Metadata/Execution映射适配使用；工具合同不兼容显示具体缺失，不改成成功。

推荐以上三类作为完整接入迭代，先做配置/保存/本地DuckDB文件闭环，再PostgreSQL与HTTP MCP真实测试。替代方案是首轮仅本地DuckDB/CSV/Parquet配置闭环，外部数据库/MCP明确延期（不是先放可用按钮骗用户）；如用户要求此缩小范围，另登记。

## 身份、上传、文件与网络边界

这是新增信任边界，方案需批准，实际网络访问/数据上传/安装按运行权限另行处理。本轮没有要求用户粘贴秘密，没有访问其任何数据库或文件。

- 首期本机开发接入管理员角色，正式多用户认证/RBAC另门禁；业务角色仅见已授权连接。所有配置/测试/执行/结果服务端再次授权，浏览器隐藏不算权限控制。
- 密码或token可在明确的专用连接表单一次提交给可信后端，URL栏/聊天/配置导入不接受明文秘密；TLS（非loopback）/日志脱敏/响应不回显/不存历史/禁缓存；引用由部署安全配置提供，不复制宿主Codex凭证。认证模式与安全保存方式需实施验证。
- MCP配置导入仅JSON，建议64KB限制、禁凭证/command/args/shell/env明文秘密；不作为图片/压缩包/任意文件加载。安全导出只非秘密字段，导入不自动发起连接；恶意字段无反射输出。
- 网络目标使用服务端管理员批准的主机/端口范围；保护metadata地址和非数据源内部服务，验证DNS/重定向目标并防重绑定、禁跳转转发认证，默认TLS校验。内网数据库需要明确允许主机，不用一刀切所有私网也不能任意地址直连。
- 先约束文件类型与大小（建议20MB首期限额，实际值待实施核验），随机内部文件名、隔离目录、校验文件头与解析限额；拒绝符号链接/路径越界/ZIP/可执行配置。上传提示数据会复制到后端、保留与删除规则，用户确认自己有使用权。
- 本机路径必须在管理员允许目录并校验resolved path，浏览器本地文件选择上传与服务端路径清楚区分。非本机部署不宣称浏览器传绝对路径就能读取用户文件。
- 不给DuckDB任意文件IO能力：可信导入阶段转入受控数据库，运行时MCP继续禁外部文件/扩展/网络IO。数据库只读专用账号、限制schema/表/列/事务/超时/返回；不导入真实公司的数据，本项目基准仍独立合成。
- 远程MCP只调用审定工具，schema/description/结果均是非可信数据；未知工具拒绝，无权限不换账号/引擎绕路。

## Worker W1受限操作与恢复切片（2026-10-27）

沿用现有pywin32，Windows目标不新增容器/依赖/服务。文件快照导入、HTTP MCP/PG目录与预览迁移到父进程持有Job的固定worker；base Python -S pipe gate在父Job分配成功后才接收配置，显式加载仅项目依赖路径，无宿主site/.pth/env秘密。默认每进程384MB/每Job512MB、Job及进程用户CPU8秒且监护总用户+内核CPU8秒、最多2子进程、父服务同时2Worker、请求64KB/输出250KB，墙钟导入25s/HTTP20s/PG12s。CPU/内存/进程限额失败拒绝而不回退无限制线程。
