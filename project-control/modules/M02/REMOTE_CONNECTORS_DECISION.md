## 推荐 A：项目专用秘密引用 + psycopg3 + 仅独立本机验证

批准评估psycopg3（含binary分发）并在许可证/兼容核实后按锁安装于现有项目venv，不升级原基础/warehouse/Excel锁。具体下载与安装按运行环境权限请求审批；如许可证或兼容不符合，回到选择，不静默换驱动。

产品配置只保存非秘密字段与secret_ref；引用仅解析用户专门为此产品提供的WORKSPACE_CONNECTOR_SECRET_命名空间和服务器绑定，不接受任意环境变量名、不扫描宿主配置、不接受聊天/JSON中的密码token。秘密由用户在可信部署渠道配置，前端只填写引用名称；后端不回显/写日志/写SQLite，缺失时明确需要配置凭证。引用不会让秘密自动成为生产安全存储；启动器仍需检查不会把这些秘密传给Vite或MCP无关子进程。

网络默认全拒绝，首轮验证只批准独立loopback HTTP fixture与用户另行明确的本机PG测试实例。配置导入不能扩大服务器白名单；外部/内网真实目标须单独批准确切主机/IP、端口、路径、用途。第一切片只支持数字IP，不用无验证DNS绕过边界；域名固定地址/TLS SNI以后另做验证。不会安装/启动PostgreSQL数据库服务或Docker，缺实际测试实例时PG集成保持not_run，不缩减完整接入验收。

取舍：非秘密配置刷新可复用，便于以后安全存储迁移；用户首次配置须在专用后端环境提供秘密引用，维护成本较低。正式认证/RBAC、跨租户、生产秘密轮换依然发布门禁。

## 替代 B：项目会话内秘密 + 同一驱动和本机验证范围

允许用户在专用连接表单一次提交密码/Bearer到可信本机API，秘密只在受限后端内存短期持有；不得URL/JSON导入、日志、SQLite或浏览器持久化。重启/过期后状态NEEDS_REAUTH，配置虽保存但需重新输入秘密和测试，不能宣称自动复连。依赖/网络范围与A相同。

取舍：配置人员无需预设秘密引用，网页路径更直接；需实现秘密TTL、原子失效、清理、会话绑定和重认证UI，不能靠仅隐藏密码证明安全。正式部署仍需要受治理秘密存储。

异步驱动asyncpg为潜在后备而非自动安装替代：异步连接池更贴近异步API，但引入不同类型/生命周期/取消实现。若psycopg核验失败再提出独立选择，不同时安装两个驱动。

## 获批后的具体切片

1. 核验/锁定驱动与批准的秘密方式；不读取宿主token，秘密哨兵验证响应、日志、SQLite、localStorage和子进程环境。
2. PostgreSQL只读专用账号/事务/statement_timeout，受授权schema/base tables导航和原类型/100行；不得WHERE筛选、删日期列或推断业务时间。
3. HTTP MCP地址/认证/受治理固定工具合同验证，测试与保存分开，刷新/版本/启停及失败下一步与本地来源一致；协议和工具不兼容拒绝，不绕过账号或权限。
4. 真正实例测试单独标real；缺实例/凭证/目标时not_run，不拿mock或配置渲染替代。再完成Worker隔离/恢复/清理、self_review与用户验收，M02未闭环前不进入M03。
