# M04-A 下一切片：真实固定文本流式测试（尚未实施）

依据现有 PRD AC02 / 已批准 ModelProvider 薄适配方向。此清单仅细化已有范围，不批准新的供应商/地址、数据外发、费用或依赖。当前 stream_verified 仍 false，不能从 generate 成功推导流式兼容。

## 用户任务与最短路径
已网页配置的本机接入管理员，在模型服务明确确认一次固定非敏感流式测试，观察来自服务端的真实进度、完成/部分/失败与用量。仍不外发表行、必要字段之外的数据、全历史或截图；不将测试结果写成本次业务问题回答，不执行 SQL/JOIN。

## 机械实施约束
1. 复用 httpx 和现有三协议薄适配，不安装第二套 Agent/SDK，不改变 LangGraph＋治理Harness 路线。优先验证已知 Messages 协议，再补 Responses/Chat Completions 的独立事件合同；不因某供应商文本通过而自动标所有协议流式 verified。
2. 正常化独立 StreamEvent：started/text_delta/completed/partial/failed_or_unknown，绑定 request UUID、配置版本、执行代际和实际模型标识。started 只是请求开始，不代表供应商成功。最终完成必须收到严格结束回执与合法用量；缺结束、断流、超限或取消不标 succeeded。
3. 仅显式按钮消费估算预留；复用全局账本、并发/行程限额与幂等回执。已存在 UUID 只读回执，不自动开启第二个上游流；失败/取消/未知保留预留，Key/厂商/重启不清账。状态、选择和刷新不计费。
4. 服务端限制响应累计字节、单事件、事件数、墙钟及输出 token；SSE 分片/多行/结束事件分别解析，不转发原始供应商对象、错误正文、thinking/signature 或工具调用。拒绝跳转、环境代理与非批准地址，继续使用既有 SSRF/DNS 固定连接传输。
5. 跨 chunk 的 Key/秘密回显检查必须在向浏览器释放内容前完成，不能仅在完整文本结尾补检查；已输出部分必须可追踪，不缓存为成功。请求/响应/历史/日志都不保存 Key，思考块隔离丢弃。流式打开/关闭期间配置锁与 provider busy 保持，禁止换Key/启禁绕过正在运行请求。
6. 浏览器只解析受限服务端事件，明确“真实流式测试/非查询”；取消、网络断连及 partial 展示有效下一步，不计时模拟字输出，不自动重试。完成后仅该协议与当前配置的 stream 能力可实测记录，其他能力仍 false。

## 验收顺序
- 隔离 provider fixture：任意网络分片、合法结束、思考丢弃、工具拒绝、模型版本不匹配、Key横跨chunk、429/超时/空流/partial、取消和预算只预留一次。
- 真实本机产品 API＋独立上游流式fixture：持续事件、并发锁、换Key拒绝、断连后未知回执、同 UUID 无重提。
- 浏览器：流式测试入口/确认、真实事件变化、部分输出/失败/恢复、主题与手机不溢出。不替换正常业务任务。
- 真实账号：用户本人加载新版、网页配置专用Key与显式操作；缺凭证/供应商流式支持时 required/not_run。公网TLS、正式身份/PG生产门禁继续保留。最后逐条审计 AC01–04，再请求整体验收，不能先进入 M03。
