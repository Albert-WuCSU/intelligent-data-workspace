## 2. 用户、问题与成功条件
**角色与情境：**业务用户保存/复用/导出分析，管理员治理生命周期，分析师追溯派生输入。
**核心问题：**将预览、聊天、任务与可授权固定资产分开，避免重启丢失或下游数字版本漂移。
**最短路径：**真实成功查询/合法上传→质检和资产登记→版本目录→授权读取/分页/临时下载→派生复用→撤权/到期/删除影响检查；历史按身份跨设备。
- 可观察成功条件以第6节逐项执行；任务完成、输入错误、权限拒绝和无数据应能被用户理解，不以测试数替代用户研究。

## 4. 非目标与失败/恢复
不把100行预览当完整分析样本，不永久公开data_ref，不保证外部已下载文件可远程撤回；不把M02 SQLite或graph memory当生产持久任务。
- 必覆盖状态：未配置/未授权/配置变更、加载、成功、空数据、不支持、超时、失败、部分/未知结果、失效、恢复；只展示本模块真实支持的操作。
- 失败保留必要非秘密输入，给出重新配置/授权/澄清/修复/重测等有效下一步；不得换账号/资源/引擎绕过拒绝或动画模拟成功。
- 业务默认看口径、来源、质量、数据和下一步；SQL/Schema及内部工具日志折叠，密钥不显示。未接能力保持明确状态，而非假按钮。
