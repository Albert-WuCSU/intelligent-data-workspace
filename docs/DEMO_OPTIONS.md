# 面试官一键体验 Demo：发布方案与边界
2026-11-06 · proposal_only · hosting / deployment not_run

## 结论
可以不租用自己的服务器，让面试官点击公开链接就体验**静态引导 Demo**，并浏览交互进度图。平台仍提供托管服务；“没有自购服务器”不等于网站无需托管。

现有真实应用依赖 FastAPI、SDK、Worker 和数据源，**仅把 Vite build 产物上传静态站点不能让真实取数工作**。`127.0.0.1` 在面试官电脑上指向他自己的电脑，不是开发者的工作台。

GitHub README 不支持执行 JS、iframe 或任意交互 HTML。合适的入口是：README 顶部“体验 Demo”按钮 → 独立 HTTPS 演示站点；图片或 GIF 内嵌、真实操作录屏另附。

## 三种方式

| 方案 | 面试官体验 | 成本和运维 | 真正展示什么 | 建议 |
| --- | --- | --- | --- | --- |
| 静态合成引导 Demo + 进度图 | 打开即可点选任务、澄清、切主题、查看来源/证据 | 不需要自购服务器；托管方案额度/价格和权限需建站时核实 | 有限脚本场景与预置合成数据，不是真实模型/仓库调用 | **先做这个** |
| 真实 Web 合成后端 Demo | 自由提问，服务端真实模型/MCP/QA | 需要后端计算、认证、资源隔离、费用预算与运维 | 受限但实际执行的产品能力 | 本机体验稳定、生产安全门禁补齐后另批 |
| 面试约定时段临时分享 | 开发者在线时可看真实应用 | 网络隧道/鉴权/限流等需单独批准；电脑须持续在线 | 本机真实流程 | 仅临时补充，不作为简历长期链接 |

录屏是可靠的辅助入口，但不是可交互 Demo。用已授权合成环境录制，去除密钥、私有路径和企业资料；从真实操作产生画面，不伪造取数成功。

## 推荐静态方案：展示与真实服务明确隔离

### 产品呈现
- 顶部醒目提示“合成引导演示 · 不调用真实模型 / 数仓”。README 按钮明确“体验合成 Demo”，不宣传为已上线生产产品。
- 独立演示入口或构建模式，复用已批准的工作台 UI；不要在现有生产/开发 API 上加一个静默返回假成功的 fallback。
- 预置取数、含糊口径确认、知识未接入、权限拒绝/预算不足等场景；分析/归因未实现时明确说明。新 D086 界面落地后再作为展示基线。
- 只使用 authored generic labels 和非敏感合成 fixtures；不让访客配置 Key、真实连接或任意上传文件。附件场景用预置合成 ID 清单；来源、数字和状态明确标示脚本演示。
- 无后台费用、无远端执行、无外发用户问题/文件；运行前测试所有点击和浏览器网络请求，禁止指向 localhost/真实 API。避免第三方统计、外链脚本和不必要追踪。
- 同站点提供当前 `docs/portfolio/progress.html`：离线快照支持主题切换、架构/进度页和模块查看，不依赖本机服务。

### 托管选项（尚未配置）
- **GitHub Pages**：适合静态站点，和仓库链接直观关联。当前仓库是否公开、账号/组织计划是否支持所需发布方式、站点访问范围，都要在 Settings 与当时文档核实；不要为上线默认将私有仓库公开。
- **Cloudflare Pages / Netlify / Vercel 静态托管**：可从经审查的静态产物部署，不需要放置应用密钥；账号权限、构建来源、额度、价格和地区可达性再核验。不同平台名不代表当前已经开通或免费永久可用。
- 如代码不适合公开，只发布**单独脱敏静态产物**；不要把完整 project-control、测试日志、配置、uploads 或私有文件当网站根目录。

### 发布步骤（执行前需批准托管与发布范围）
1. 先完成 D086 QF-UI/QF-ROUTE 最小用户路径，确定真实版和演示版能力标签。
2. 实现独立纯前端演示适配器，编写有边界标识的合成场景；验证无凭证/模型/数据源访问。
3. 生成演示构建、最新脱敏进度页与预览图，检查键盘、黑白主题、手机和断网行为。
4. 确认允许公开的产物、平台账号/域名/费用及访问范围，然后部署；不得凭本方案自动上线。
5. 在非开发者设备/无登录窗口打开公开 URL 走完任务，证实不是 localhost；验证数据不外发。
6. 验证后才在 README 顶部加入真实 HTTPS 链接，保留“合成 Demo”标识；不得预填尚不存在的线上地址。

## 真实后端 Demo 为什么不能直接公网化
当前默认开发身份与 Windows Job Object/Worker 路径不是多用户生产安全方案。真实发布需先核平台/操作系统适配、HTTPS、认证、会话隔离、模型预算硬限额、限流、工具和网络白名单、数据源scope、存储保留与审计。模型 Key 只能由后端秘密管理提供，不能放 Vite 环境变量、静态 JS、URL 或仓库。

仅用合成仓库也不能略过权限与资源门禁；访客无限模型调用会产生费用。选择 Linux/容器平台还需适配并实测现有 Windows 隔离，不可直接承诺一键部署。不开新真实账单、不重置 D053；独立演示费用需批准，不能挪用旧测试预算。
