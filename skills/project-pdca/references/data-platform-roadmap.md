# 智能数据平台推荐实现路线

## 起点与选型原则

产品策划方案是输入，不等于实现授权。开始先确认目标客户场景、MVP边界、部署及真实执行平台。若已有代码或用户决策则延续，不强制重建。每一模块都执行Skill的PDCA，共享栈批准一次，本模块只有新增或替换才开选型决策。

推荐基础：Python/FastAPI/Pydantic后端、React/TypeScript前端、PostgreSQL控制面、Arrow/Parquet结果载体、S3兼容存储接口、pytest及前端适用测试工具。小型团队先模块化单体与独立Worker，不先上全量微服务、Temporal、Kubernetes、向量库或JupyterHub。实际包版本、许可和平台兼容先验证。

## 本项目已批准的模型服务前置路线

对universal-data-agent：D-ROADMAP-MODEL-014的M02→M04-A→M03→M04（M04-B）顺序保留；D-M04B-CLAUDE-SDK-070将当前编排主线替换为Claude Agent SDK＋产品Skills＋治理Harness。LangGraph保留比较分支codex/langgraph-baseline-20261103及旧证据，不自动继续开发图主线。其他项目不强制此路线。

先Skill路由/澄清和授权内探索，再指标优先或受控SQL，取数工具内部必过质量检查，发布入口校验回执。Prompt/技能文档不替代代码安全，工具名称不代表当前助手的权限可继承。SDK工具循环不是无限执行；独立环境/设置目录、工具暴露与服务器门禁、费用预留/幂等、许可及网关兼容在PLAN核验。具体约束见[SDK迁移](claude-sdk-routing.md)。SDK版本/安装/真实调用尚未获本次文档变更的自动授权；生产/PG后补等原门禁保持。

## 推荐模块

| 模块 | 目标与栈候选 | 必须演示及审计 |
| --- | --- | --- |
| M01 工程底座与合同 | 共享栈、目录、配置、任务/QuerySpec/资产Schema、身份接口、测试基座 | 可启动、Schema校验、身份不信任客户端tenant_id、错误与日志不泄漏 |
| M02 MCP元数据与SQL执行 | 统一Metadata/Execution适配、MCP客户端、客户Spark/Hive服务或现有Adhoc接口 | 获取授权真实字段、提交只读SQL、状态、结果、错误；取消不支持要显式记录 |
| M03 企业语义知识库 | 结构化Domain Pack、YAML/JSON导入、Pydantic校验、关系存储；RAG按需 | 口径、术语、实体、表映射及关联、版本审批、冲突澄清；无审批不认证 |
| M04 取数Agent与Harness | 确定性状态机、模型适配、SQLGlot加引擎方言检查 | L1/L2/L3/L4、串行依赖、澄清、只读权限及预算、执行前后质检、拒绝不绕路 |
| M05 数据资产与任务 | 受保护Parquet/Arrow、对象存储接口、元数据目录及持久任务 | 快照/口径/来源/质量/权限、幂等、分页、过期、读取鉴权、下游回主干补数 |
| M06 可视化工作台 | React、ECharts或Vega-Lite、声明式Chart/DashboardSpec | 从真实资产画图、单位和聚合正确、筛选与刷新、版本、XSS及未授权访问检查 |
| M07 证据化报告 | 网页ReportSpec、按需求文档导出、claim_id引用 | 数字来自固定资产版本，图表一致，局限及审阅发布；外发需授权 |
| M08 MVP集成与交付 | 真实端到端、身份/限额/日志、安装配置及回滚 | 从提问到SQL/资产/大屏/报告，对账、跨租户、真实环境和用户验收 |
| M09 指标归因 | Python分析库、结构/漏斗/比率分解、可复现方法 | 分解守恒、残差、可比窗口、小样本及局限；贡献不称因果 |
| M10 建模工作台 | 成熟Notebook内核、独立容器、按需Monaco；MLflow非首期必选 | 上传隔离、手写/Agent代码、输入版本、依赖、基线、泄漏、资源/网络隔离 |
| M11 实验分析 | Python统计库、历史AB及合适DID设计 | AB分流单位/SRM/置信区间/多重查看；DID对照、处理前与错位实施检查 |
| M12 企业接入与完整发布 | SaaS SDK/iframe/API、SSO、私有数据面及连接器认证按需 | 部署与模型驻留边界、OEM租户映射、全模块集成、安全与运维最终审计 |

M01先冻结最小资产/任务合同供M02/M04沿用，M05再实现完整生命周期，避免上游取数等到M05才有可交付结果。基础身份和权限从M01贯穿全部模块，不推迟到M12才加。部分企业SSO/私有部署若首批客户需要，则前置到MVP，重新排依赖。

M02不绑定不存在的Spark/Hive MCP标准端点；先检查用户实际可用服务、协议、鉴权及环境。项目当前会话的MCP工具可用于获授权PoC，但不能假设将来应用进程和新会话自动继承这些连接或令牌。要为产品配置独立、合法可部署的连接器。

## 每模块技术决策的内容

列出已批准的继承项、本模块新增项、至少一种真正可用的替代路线、Windows本地与目标部署兼容、成本、维护、许可、迁移和锁定风险。不要为了“每模块选型”强行重复选择前端或数据库。没有真实数据连接时优先把元数据/执行合同做好，允许做本地适配开发，但真实联通门禁保留。

## 首次选择建议

建议先采用“精简MVP”：M01至M08形成真实问数→资产→大屏→报告闭环，M09至M12保留完整目标但不提前详细实现。推荐模块化单体、本地开发加后续受控部署；真实执行路径以用户现有Spark/Hive或Adhoc平台为准。用户也可优先采用取数验证路线，只把M01至M05作为第一里程碑，验证后再投入UI。

范围、部署和执行入口可以在一张方案卡中确认，但其中的未知凭证和网络条件必须单独标明，不能因为采用推荐范围就默认授权外部查询。在线实验分流是M11之外的独立扩展，需用户另行批准。

## 已确认产品交互约束的读取

恢复本数据平台项目时读取project-control/PRODUCT_UX_PRINCIPLES.md。业务取数默认走历史会话/连续对话/顶部真实执行状态/结果摘要路径；契约编辑器只用于开发工具。结果先结论及口径，再来源/质量/附件，SQL和Schema折叠。双主题入口显式黑色/白色并显示选中态。M02连接器面向管理员配置、测试和诊断，业务用户只需理解接入是否可用。M05细化服务端鉴权会话及资产历史，不延续开发localStorage作为生产授权。

产品经理应聘作品应保存方案取舍与证据，不自动替换现有UI或编造成功数据、访谈、商业收益。继续推进先处理当前模块的方案及真实资源选择，不回到已验收M01重新开发。
